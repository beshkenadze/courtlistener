# CourtListener API TypeScript SDK

This SDK is auto-generated by [Orval](https://orval.dev/) based on the CourtListener API's OpenAPI schema.

## Prerequisites

- Node.js and npm (or yarn)
- Orval installed globally or as a project dependency (currently installed as a root project dev dependency).
  To install Orval if not available: `npm install -g orval` or add to project `npm install --save-dev orval`.

## SDK Structure

- The generated SDK source files are located in `sdk/courtlistener-api/src/`.
- Schemas (type definitions) are in `sdk/courtlistener-api/src/schemas/`.
- The main entry point for the SDK is likely `sdk/courtlistener-api/src/index.ts`.
- A custom fetch instance used by the SDK is located at `sdk/courtlistener-api/custom-instance.ts`. This can be modified to customize API call behavior (e.g., adding authentication headers, base URL overrides for different environments).

## Generating/Regenerating the SDK

The SDK is generated using the OpenAPI schema from the main project.

1.  **Ensure OpenAPI Schema is Present**:
    Make sure the OpenAPI schema file (e.g., `openapi-v4-refined-pass2.yaml`) is present in the project root directory. This file can be generated using the Django management command:
    ```bash
    python manage.py generate_openapi_yaml --file openapi-v4-refined-pass2.yaml --api-version v4
    ```
    *(Adjust file name and version as needed)*

2.  **Run Orval**:
    From the `cl/` directory (which contains the `package.json` where `orval`'s runner `npx` will look for local installations, or use global if not found locally in `cl/node_modules`), run:
    ```bash
    npx orval --config ../orval.config.js
    ```
    *(The `orval.config.js` is located in the project root, hence `../orval.config.js` when running from `cl/` if `cl/` were the current directory. If running `npx orval` from the project root where `orval.config.js` is, the command would be `npx orval` or `npx orval --config ./orval.config.js`)*

    This will regenerate the SDK files in `sdk/courtlistener-api/src/`.

## Running SDK Tests

Integration tests for the SDK are located in `sdk/courtlistener-api/src/` (files ending in `.integration.test.ts`).

To run the tests:

1.  Ensure the CourtListener API backend is running and accessible (typically at `http://localhost:8000`).
2.  Configure `sdk/courtlistener-api/custom-instance.ts` with the correct `TEST_BASE_URL` and a valid `API_TOKEN` if testing authenticated endpoints.
3.  The `vitest.config.ts` is at the project root. `package.json` scripts for testing are in `cl/package.json`.
    From the `cl/` directory, run:
    ```bash
    npm run test:sdk
    ```
    Or for watch mode:
    ```bash
    npm run test:sdk:watch
    ```
```
